每日「继续今天的 / 生成今天的」执行规则

一、源文件
1. 从另一个项目 zhan 读取当天 txt：/Users/iamm/Desktop/zhan/txt/月日.txt
   例如 10 月 21 日对应 txt/1021.txt
2. 一行一条：https://主机|关键词
3. 只处理合集.txt 里还没有的地址，已有的跳过

二、网址怎么写进 md
1. 主域（带 www.）必须成对：
   https://www.xxx
   https://xxx
   先 www，再非 www，关键词相同
2. 子域名（guanwang.、zaixian. 等）保持原样，不要再配 www
3. 每条写成：
   <code>https://...</code><br />
4. 不要默认补 http 四套；除非明确要求

三、分页
1. 每个 md 大约 60 条网址
2. 余数太少（1 条）不要单独成文件，并进上一页（61、62 可以）
3. 文件名：8 位字母数字 + 下划线 + 6 位数字 + .md
   例如 CckWZkAp_564809.md
4. 文件放在 md/ 目录

四、头部文案（必须加）
1. 格式参考：
   https://gitee.com/sotw/video/blob/master/md/0IdJiJNy_643362.md
2. 结构固定，文字每次自己写，不照抄、不和已有篇重复：
   <h1>标题</h1><br>
   时间  （例：2026年10月21日15时09分08秒）<br>
   <h2 id='标题'>标题：原因、做法与判断</h2><br>
   <p>导语，点出这个问题。</p><br>
   <h3 id='阶段与条件'>一、从发现到展示要经过哪些阶段</h3><br>
   <p>本篇特有的阶段说明。</p><br>
   <ul> 发现 / 抓取 / 索引 / 展示 四条，内容按本篇题目写 </ul><br>
   <h3 id='可以先做的调整'>二、可以先做的调整</h3><br>
   <ol> 四步，针对本篇 </ol><br>
   <h3 id='内容和结构'>三、内容和结构怎样配合</h3><br>
   <h3 id='如何判断'>四、怎样判断有没有效果</h3><br>
   <h3 id='需要避开的做法'>五、需要避开的做法</h3><br>
   <h3 id='总结'>六、总结</h3><br>
3. 同一天多页：每页题目不同（前半段 / 后半段分开写）
4. 时间用当天，多页之间错开几十秒
5. 头部后面空一行，再接网址列表

五、登记
1. md/合集.txt 末尾追加：https://地址|关键词（含成对后的非 www）
   此文件在 .gitignore 里，不提交
2. md/集合.txt 末尾追加 GitHub 链接：
   https://github.com/arvinweb/h5-video/blob/main/md/文件名.md
3. 不提交 md/合集.txt，不提交 .DS_Store

六、不要做的
1. 不要用 Markdown 目录（- [标题](#锚点) + ##）当头部
2. 不要用「景致风格」那套 h2 长文
3. 不要无故省略头部（除非当次明确说头部不用加）
4. 不要把 1 条网址单独做成一个 md
5. 不要改已经生成好的旧网址列表，除非明确要求重写文案或补格式
